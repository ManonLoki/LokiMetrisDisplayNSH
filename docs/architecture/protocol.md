# 局域网协议

[应用架构](overview.md) · [移动使用](../mobile/usage.md) · [配对库来源](../provenance/pairing-core.md)

展示端通过局域网发现电脑，使用四位码首次配对，再以保存的身份恢复认证会话。五个平台共用 `src/native/connection/`；桌面采集端与展示端分别编译同一固定提交的 `loki_metris_pairing`，通过直接 TCP 和应用层加密协议通信。

## 运行时边界

`src/app/runtime.ts` 只保留 250ms 的 UI 时钟和信号赋值；启动、轮询、保存名称/面板和命令转发都由 Rust 的 `Shell` 模块（`src/native/shell.rs`）完成，它在内部驱动真实连接。`Shell` 注册的接口为：

| 接口 | 职责 |
| --- | --- |
| `Shell.start()` | 恢复身份和偏好，按平台初始化私有目录和当前 VM 的连接 owner，返回首个公开状态 |
| `Shell.tick(draft, nowMs)` | 轮询最近提交的公开连接状态与已验证图片 URI，并推进名称确认的时钟 |
| `Shell.command(command, …)` | 将用户意图（选择、遗忘、刷新等）加入有界队列并立即轮询 |
| `Shell.editName` / `saveName` / `savePanel` | 编辑名称草稿、保存名称与面板偏好；需要连接执行的命令由 `Shell` 自己下发 |
| `Shell.dispose()` | 结束设置会话并告知连接界面不再活动 |

owner 串行管理发现结果、选中来源、配对、认证恢复、会话序号、心跳、快照和图片接收。TCP 读写与发现线程只提交事件，不能另建一套协议状态。`System.locals` 持有连接实例，VM 关闭时释放。

| 命令 | 参数 | 行为 |
| --- | --- | --- |
| `discover` | 无 | 重新发现局域网来源 |
| `select` | `clientId` | 配对新来源，或恢复已保存来源的认证 |
| `forget` | `clientId` | 删除安全记录；清空该来源当前展示与快照缓存 |
| `rename` | `name` | 保存名称，供后续配对或认证使用 |
| `active` | `value` | 提交界面活动状态；移动端忽略此命令，改用系统观察结果 |
| `refresh` | 无 | 已连接且桌面支持时请求快照，否则重试连接 |

移动端的生命周期和网络事实走原生宿主接口，不能由 JavaScript 伪造。面板偏好由 Rust 设置用例（`src/features/settings`）经 NSH Storage 保存；配对秘密留在 Rust 与系统安全存储，公开投影不包含秘密或读取凭据的能力。

## 发现与配对

服务类型为 `_loki-host._tcp.local.`。iOS 使用系统 Bonjour，其余平台使用 `mdns-sd`；Android 在前台持有必要的多播资源。发现结果须具有合法协议版本、UUID、名称和端口，地址只接受私网或链路本地 IPv4。广告提供候选地址，信任由认证建立；重复声明同一身份的来源不能选择。

用户在前台选择未配对来源时，才开启 60 秒四位码窗口。配对使用共享库的 SPAKE2 接收端对象；取消、切换或离开前台会撤销本轮资格，传输重试沿用原窗口。桌面确认后，展示端先实际持久化凭据，再生成保存 ACK；存储失败、过期或取消时不发送成功确认。

已保存来源使用共享库的会话 API 恢复认证。只有收到通过校验的完整快照，界面才标记为在线。

## 传输与凭据

TCP 帧由 4 字节大端长度和 JSON 正文组成，握手帧上限 4096 字节，加密帧上限 96 KiB，发送队列最多 8 帧。先验证声明长度再读取正文，握手阶段由 owner 逐帧推进；连接、读写、认证和心跳均有期限。

安全消息由共享库封装、认证和解密。认证失败、重放、错误序号或非法消息会关闭连接；加密已消耗序号后若发送失败，关闭通道并重新认证。

| 平台 | 配对记录存储 |
| --- | --- |
| macOS、iOS/iPadOS | Keychain |
| Windows | Credential Manager |
| Linux | `secret-tool` 对接当前用户的 Secret Service |
| Android | 私有加密文件；随机密钥由 Android Keystore 包裹 |

安全存储不可用或锁定时返回错误。读取失败不能当作空记录覆盖，存储也不会回退到明文。

## 快照、图片与离线状态

认证快照经 Rust 校验后更新接收时间，再投影为用量、额度和 Hook。收到图片清单后，owner 按当前 Hook 的引用顺序请求缺失资源。共享接收器检查偏移、Base64、长度、MIME 魔数和 SHA-256；完整写入、同步、原子改名并读回验证后，才向界面暴露本地 URI。单图上限 32 MiB，磁盘缓存受数量和空间限制；单张图片超时或缓存写入失败时，文字与用量仍可显示。

| 平台 | 连接中断或离开前台后的快照 |
| --- | --- |
| Windows、macOS、Linux、iOS/iPadOS | 保留最近缓存及真实接收时间，撤下实时状态 |
| Android | 清空展示，不保留或恢复离线快照 |

移动端离开前台后暂停桌面连接，回到前台再恢复。忘记当前来源或切换来源会撤下对应展示和快照；iPhone 同时提交 Watch 的清空状态，见 [Watch 配套架构](watch-companion.md)。

GIF 由应用 Rust 后台工作线程准备为完整画布 PNG 帧，TSX 播放时钟控制帧序列。后台、页面不可见或启用减少动态效果时暂停，有限循环停在末帧。静态图片和各帧均由官方 NSH Image 展示，详见 [运行时说明](../provenance/nsh-runtime.md)。

## 调试入口

`cargo run --example protocol_host` 启动隔离账本的局域网夹具，适用于配对、会话恢复与资源传输验证。统一测试入口、环境要求和真机验证范围见 [测试说明](../development/test.md)。
